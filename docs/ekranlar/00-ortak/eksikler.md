## 3. Kısmi karşılıklar
- **E-00-07 program alt metni "2026 sezonu":** `Program.year` (integer) var ama **isteğe bağlı**; "sezon" dizesi yok. Alt metin `"<year> sezonu"` istemcide kurulur, `year` yoksa gizlenir. Eksik açılmaz.
- **E-00-14 / E-00-15 Admin merceği:** `reportDashboard` (`DashboardReport.overdue_tasks`, `pending_date_changes`) tek S2 istekle verir; ancak yanıt bütün pano verisini taşır (ağır) ve yalnız `company_admin`'e açıktır (REPORTING-K01). Kabuk rozeti için kabul edilebilir; yeni-3 sayaç ucu gelince ona taşınır. `pending_date_changes` ve `pending_approvals` kodda var ama backend testinde sınanmıyor (GAP-075). **Varsayım:** iki sayının tanımı (geciken = `is_overdue`; bekleyen talep = programdaki `pending` talepler) liste alanlarıyla aynı — backend reporting README'den doğrulanmalı.
- **E-00-14 Koordinatör/Üye merceği — tek istekli ara çözüm (karar gerekir):** seçili tek departman için `coordinatorGantt` / `memberGantt` (S3) satırlarında `lateness.is_overdue` sayılabilir; fan-out değildir ama ilk 200 kalemle sınırlıdır (GAP-053) ve her ekranda Gantt yüklemek pahalıdır. Öneri: kullanılmasın, rozet yeni-3 kimliğiyle `designStub` altında gizli kalsın (bkz. §4 soru).
- **E-00-40 / ozellikler §7.1 dar menüde "birim kodu" (kapsam simgeleri; CX-M-08):** `MyDepartment` satırında `code` yok; `Department.code` taşıyan `listDepartments` yöneticiye özeldir (`organization.not_authorized`). Ama `listProgramDepartments` (S2, programda ekip satırı olan herkese açık) `ProgramDepartment.code` (isteğe bağlı) taşır → `department_id` ile eşlenerek alınabilir. `code` boşsa baş harf. Eksik açılmaz; kolaylık için `MyDepartment.code` önerisi koordinatörün takdirine (S).
- **E-00-21:** `unread_chats` sohbet sayısıdır (bkz. yeni-1); `mentioned` bayrağı tasarımda kullanılmıyor.
- **E-00-38:** sayaç hesap genelidir, program değişince değişmez.
- **E-00-02 ürün adı:** "RoketPortal" sabit metin mi, `instanceProfile.display_name` (kurulum görünen adı) mı belli değil; sözleşmede kurulum adı vardır. Sürüm "v2.0" backend alanı değildir (istemci derleme sürümü).
- **E-00-36 tarih:** tasarım istemci saati der; sözleşmede `instanceProfile.timezone` vardır — kurulum saat dilimiyle biçimlemek önerilir.
- **Liste tavanları:** `listPrograms`, `myDepartments`, `listProgramDepartments` ≤200 + `X-Result-Truncated` (GAP-027); tasarımda kesilme göstergesi yok — menü sonuna nötr "liste kısaltıldı" satırı (istemci metni) önerilir.
- **`listPrograms` sırası** spec'te belirtilmemiş; menü sırası istemcide (ad, `tr-TR` karşılaştırma; GAP-036) kurulur.

## 4. Yol haritası kararıyla çelişenler
- **K3 / istemci-akislari §2, §6 ↔ E-00-14, E-00-15 (Koordinatör/Üye):** sayaç ucu olmadan rozet yalnız `listProgramWorkItems`'ın bütün sayfalarını gezerek hesaplanabilir; bu aynı ucun sayfalamasıdır, K3'ün departmanlar arası fan-out yasağına girmez (ortak-kurallar §9; CX-T-05) ama her ekranda tam tarama maliyeti demektir ve §6 "sayı yüklenmiş satırlardan" kuralının kabuğa genişletilmesi olur. **v1'de:** Admin merceğinde `reportDashboard` ile gerçek, Koordinatör/Üye merceğinde rozet gizli + `designStub` (yeni-3). Ürün sahibine soru: v1'de koordinatör rozeti için Gantt tabanlı yaklaşık sayım (§3) kabul edilir mi?
- **K6 metni ↔ sözleşme:** K6 `organization.not_authorized`'ı yetki kaybı tetikleyicisi sayar; bu kod yalnız 27 organizasyon yönetim ucundan döner (kabuk ve görev uçlarından hiç dönmez) — tetikleyici olarak zararsız ama kapsam kaybını yakalamaz. Buna karşılık seçili program görünmez olduğunda dönen **404 `program.not_found`** (`readProgram`, `listProgramDepartments`, `reportDashboard` ve diğer `report*`) K6 listesinde yok. Koordinatöre öneri: K6 listesine `program.not_found` ve `reporting.not_authorized` eklensin; `organization.not_authorized` "yöneticilik kaybı" olarak kalsın.
- **K7 "departman ataması bekleniyor" ↔ mekanizma §6:** bu durumda yalnız rol/koordinatörlük kartı boş kalmaz — `listPrograms` doğrudan 403 `organization.membership_required` döner, program kartı da yüklenemez. `myDepartments` ise 200 + boş/`null` döner (bu kodu döndürmez). Açık durum ekranı `listPrograms` 403'üyle tetiklenmeli.
- **K14 ↔ E-00-18 Arşiv, E-00-20/21 Mesajlar, E-00-39 Asistan:** uçlar sözleşmede mevcut (F5/F7/F8) ama v1 (F0–F4) dışında; görünürlük ürün sahibi kararı (README açık sorusu). Backend eksiği değildir.
- **K1 ↔ Yönetim grubu (E-00-11, E-00-23…25):** tasarım "Admin merceği" der; sözleşmede bu ekranların okuma uçları yönetici olmayana 403 döner (`organization.not_authorized`, program yazmalarında `program.not_authorized`). Capability = `me.company_admin`; mercekten bağımsız (Admin olup Koordinatör merceğindeki kullanıcı da yönetim ekranına erişebilir; tasarımın Admin-only gruplaması bilinçli sapmadır). **Karar (ortak-kurallar §1):** yönetici Koordinatör merceğine geçince Yönetim grubu görünür kalır, `listUsers` 403 dönmez; mercek yetki değil kapsamdır (CX-T-04, CX-M-02). Açık soru kalmadı.

## 5. Önerilen backend iş paketleri
1. **P1 — Kapsam rozet sayaçları (yeni-3, S; bağ GAP-075):** `GET /v1/program/work-items/counts` (S2; `department_id` isteğe bağlı; görünürlük `listProgramWorkItems` ile aynı): `overdue`, `pending_date_requests`. Kenar menüsü rozetlerini (E-00-14/15) bütün merceklerde kapatır, kabuğun testsiz `reportDashboard` alanlarına (GAP-075) bağımlılığını kaldırır. BE-003'ün (03 liste: `total` + durum başına sayı) aynı uca eklenmesi backend'in takdiridir; F0 kabuğu yeni-3'ü, F1 listesi BE-003'ü tüketir. Ayrıca GAP-075 kapanırsa (pano sayaçlarına test) Admin rozeti güvenceye girer.
2. **P2 — Program kısa ad + renk (BE-001, S):** `Program.short_name`, `Program.color`; program yazma uçlarına isteğe bağlı alanlar. F2 "Teknofest ve sezon" formu da tüketir. Kırıcı değil.
3. **P3 — Web uyumluluk politikası (yeni-2, belge + koşullu BE, S):** önce compatibility.md §3'e web uyumluluk politikası; politika gerektirirse `InstanceProfile.minimum_web_version` (ya da sözleşme etiketi). Ürün sürümü–pin minörü karşılaştırması önerilmez (ortak-kurallar §11). Bağımsız; KR-11/GAP-016 kararıyla birlikte.
4. **P4 — (koşullu, F7) okunmamış mesaj sayısı (yeni-1, S):** `ChatUnreadProgram.unread_messages`; yalnız ürün kararıyla.
5. (isteğe bağlı, S) `MyDepartment.code` — dar menü birim kodu için `listProgramDepartments` birleştirmesini gereksiz kılar.
