# 03c — Backend eşlemesi (nereden geliyor)

Kaynak: `../../../../nizam.io--backend/docs/api/openapi.yaml` (pin `v0.11.0-api`), `istemci-akislari.md`, `error-codes.json`. İstemci uydurmaz; uyuşmazlık `eksikler.md`'ye gider.

Ek kaynaklar (backend deposu): `docs/architecture/adr/0024-gorev-kaniti-ve-alt-gorev.md`, `docs/known-gaps.md` (GAP-053, GAP-204), `internal/modules/work/README.md` (WORK-K36, K37, K40, K74, K82).

**Ana bulgular (özet):**
- Üç yüzün yanıt şeması aynıdır: `Gantt { tasks: GanttTask[], links: GanttLink[] }`. `GanttTask` **yalnız** şu alanları taşır: `work_item_id`, `title`, `program_id`, `department_id`, `priority`, `status`, `start_on`, `end_on`, `planned_end_on`, `completed_on`, `assignee_account_ids`, `lateness{is_overdue, days_overdue, is_completed_late, days_late, is_completed_early, days_early}`.
- `GanttTask`'ta **yok:** görev kodu, departman adı, atanan adları (`assignees`), `pending_date_request`, `subtask_counts`, `dates_revision` / `edit_revision`, `completion_evidence_required`, alt görevler. (`WorkItem` — liste/tekil — bunların hepsini kodu hariç taşır.)
- `start_on`, `end_on`, `planned_end_on`, `completed_on` `GanttTask`'ta `type: string` (biçim belirtilmemiş); `planned_end_on` ve `completed_on` için "boşsa" deniyor → istemci **boş dizgeyi** "yok" sayar (null değil). `status` `GanttTask`'ta enum değil (WorkItem'daki beş değer beklenir).
- `coordinatorGantt` ve `memberGantt` **S3**'tür (program + departman başlığı zorunlu) → tek departman. `adminGantt` **S2**'dir, `overdue` süzgeci alır.
- Tarih yazımında sürükleme/panel için üç yol vardır ve hiçbiri "geri al" taşımaz (§2, §6).

## 4. Türetilen değerler (istemcide hesap)
- **Başlık sayaçları (E-03C-02):** `N görev` = `tasks.length`; `N bitti` = `status == "tamamlandi"` sayısı; `N gecikmede` = `lateness.is_overdue` sayısı. Kaynak seçili yüzün Gantt yanıtıdır → yalnız sunucu `X-Result-Truncated: true` bildirdiğinde **yaklaşık** ("N+", "yüklenen kayıtlar içinde"; BE-019, pin v0.15.0-api; tam 200 başlıksızsa sayaçlar kesindir). Kesilmede sayaç yanına tavan uyarısı (E-03C-82). `reportSeason.stats` (yalnız yönetici, REPORTING-K01) kullanılmaz: yüzler arasında tutarsız olur.
- **Grup sayacı `bitti / toplam` (E-03C-28):** `department_id`'ye göre gruplanmış `tasks`'tan; aynı yaklaşıklık.
- **Durum süzgeci (E-03C-06):** `acik` = `status != tamamlandi` (**Varsayım:** "Açık" tamamlanmamış her durumu kapsar — doğrulanacak: ürün sahibi, `ozellikler.md` §7-8), `geciken` = `lateness.is_overdue`, `biten` = `status == tamamlandi`. Admin'de `overdue=true` parametresi kullanılmaz (GAP-053 anlam farkı; ayrıca süzgeçte ham sayı/tavan uyarısı bozulur).
- **Koordinatörlük süzgeci (E-03C-05):** yalnız Admin yüzünde, `department_id` üzerinden istemcide (tek `adminGantt` yanıtı; K3 fan-out yasağı). Koordinatör yüzünde departman değişimi kenar menüsünden, yeni `coordinatorGantt` isteğiyle.
- **Çubuk geometrisi (E-03C-36, 40):** plan = `start_on` → (`planned_end_on` || `end_on`); taşma ucu = `is_overdue` ise bugün, `is_completed_late` ise `completed_on`. Gün sayıları `days_overdue` / `days_late`'ten (istemci yeniden hesaplamaz; WORK-K37 TRT takvim günü kuralı sunucuda).
- **Süre `<n> hf` (E-03C-39):** plan aralığından istemcide.
- **Sezon histogramı (E-03C-15):** yüklü `tasks`'ın haftalara dağılımı — yaklaşık. **Varsayım:** sayılan, plan aralığı haftayla kesişen görevdir (doğrulanacak: ürün sahibi / tasarım, `ozellikler.md` §7-5). Sezon aralığının kendisi yok (`eksikler.md`); geçici: **Varsayım:** sezon = yüklü görevlerin en erken `start_on` – en geç bitiş aralığı (doğrulanacak: ürün sahibi; kalıcı çözüm `eksikler.md` yeni-4).
- **Bağımlılık simgesi (E-03C-37):** `links` içinde `target == work_item_id`. **Varsayım:** simge yalnız ön görevi olanda (doğrulanacak: ürün sahibi / tasarım, `ozellikler.md` §7-4); kaynağı olan da işaretlenecekse `source` da taranır.
- **Bildirim farkı "bitiş +N gün" (E-03C-69):** uzatmada `days`; `updateWorkItem` ile değişimde eski/yeni `end_on` farkı. Bağımlı kayması `cascade_count`/`affected_tasks_count`.
- **Alt görev çipi / ilerleme (E-03C-44, 46):** Gantt'ta veri yok. Seçili görevde `getWorkItem.subtask_counts`'tan gerçek değer gösterilebilir; diğer satırlar statik (BE-020).

## 5. Sorgu anahtarları ve geçersizleme
- `scopedKey(['work','gantt', yüz, programId, departmentId|null])` — yüz ∈ `admin|koordinator|uye`; admin anahtarında departman yok, `overdue` parametresi anahtara girmez (kullanılmıyor).
- `scopedKey(['work','item', programId, departmentId, workItemId])` — panel `getWorkItem` (03 ile **aynı** anahtar paylaşılır).
- Görev dosyaları: `scoped(['work-items', id, 'files'])` (`ortak-kurallar.md` §6; **03 ve 06 ile ortak**, grup kendi anahtarını yazmaz — CX-T-01).
- `scopedKey(['work','dependencies', …, workItemId])`, `['work','subtasks', …, workItemId]` — 03 ile paylaşılır.
- Departman adları: bütün yüzlerde `scoped(['departments'])` (`listProgramDepartments`, `ortak-kurallar.md` §6; CX-T-03); `['me','departments']` (kabuk) yalnız kapsam seçimi için.
- **Geçersizleme:** `updateWorkItem`, `extendWorkItem`, `reviewDateChangeRequest` → Gantt (ilgili program altındaki **bütün** yüz anahtarları; zincir başka departmanı kaydırabilir), `work.item` (görev + bağımlıları için tüm `work.item` önekini), `listProgramWorkItems` sayfaları. `requestDateChange` → `work.item` (seçili) + liste + Gantt (Gantt alanı değişmese de 03 sayacıyla tutarlılık). `addDependency`/`removeDependency` → Gantt + `work.dependencies`. 03'teki durum geçişi, oluşturma, silme, aktarım → Gantt. Alt görev yazımları → `work.item` (sayaç) — Gantt'ı etkilemez.
- Kapsam değişince (K2) Gantt sorgusu iptal, panel kapanır; panel taslağı "sonuç bilinmiyor"da korunur (K5).
